# Підготовка до захисту (Q&A)

Цей документ містить орієнтовні запитання комісії та тези відповідей за результатами кожної фази розробки.

## Фаза 0 — Організація проєкту та стек

1. **Чому для проєкту обрано JavaScript (ESM) та монорепозиторій на npm workspaces замість двох окремих репозиторіїв?**
   - Зафіксований стек (ESM без TypeScript) дозволяє швидко синхронізувати скрипти встановлення, лінтингу, тестування, збірки та запуску з єдиного `package.json`, а також спрощує деплой одним сервісом на Render.

2. **Для чого потрібен ендпоінт `GET /api/health` уже на старті?**
   - Він використовується для smoke-тестування API (Supertest) та для автоматичних health-check перевірок хостингу (Render) під час деплою.
